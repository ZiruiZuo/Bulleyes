# External LGE Scar Mask Bullseye Workflow Design

## 1. Background and Goal

The LGE workflow is split into three independently usable capabilities:

1. The standalone `lgeMask` tool selects normal-myocardium reference ROIs and generates `lge_scar_mask.nii.gz`.
2. A new `cardiac-lge-mask-bullseye` command accepts an existing scar mask, asks the user only for AIP/IIP landmarks, and generates the requested bullseye figures.
3. The existing `cardiac-lge-bullseye` command remains the complete workflow: AIP/IIP annotation, normal-myocardium ROI annotation, internal `mean + n * sample SD` scar calculation, and bullseye generation.

The new command must not invoke normal-myocardium ROI selection or recompute scar. It must share AHA segmentation and rendering code with the complete workflow so that both commands produce equivalent figures from equivalent inputs.

## 2. Selected Architecture

### 2.1 Public commands

| Capability | Command | Interactive work |
| --- | --- | --- |
| Create a scar mask | Standalone `lgeMask` tool | Normal-myocardium ROI selection |
| Render from an existing scar mask | `cardiac-lge-mask-bullseye --config <file>` | AIP/IIP annotation only |
| Run the complete workflow | `cardiac-lge-bullseye --config <file>` | AIP/IIP and normal-myocardium ROI annotation |

The new command is added to the existing `cardiac-bullseye` Python package. No additional standalone project or duplicate rendering implementation is created.

### 2.2 Internal boundaries

- `lge_mask_bullseye` workflow: owns configuration selection, external scar-mask loading, fresh AIP/IIP annotation, and orchestration of the three requested outputs.
- Existing `lge_bullseye` workflow: continues to own normal-ROI selection and internal scar-mask calculation.
- Shared rendering core: receives a loaded LGE study, landmarks, a prepared scar mask, deleted slice indices, and mapping parameters. It computes AHA 1-16 segment IDs, native LGE intensity mapping, segment scar percentages, and both figures.
- LGE I/O layer: owns three-image physical-grid validation, foreground conversion, common cropping, and scar-within-myocardium validation.

The shared core is non-interactive and does not read configuration or select files. This keeps it reusable and independently testable.

## 3. Configuration Contract

The new workflow uses its own TOML section and configuration dataclass. It does not overload `[lge_bullseye]` or change the meaning of the existing complete workflow.

```toml
[case]
id = '032602'
output_directory = 'outputs/032602_lge'

[lge_mask_bullseye]
lge = 'data/lge_sax.nii.gz'
mask = 'data/lge_myocardium.seg.nrrd'
lge_scar_mask = 'data/lge_scar_mask.nii.gz'

angle_count = 360
radial_count = 300
angular_smoothing_sigma_deg = 1.5
radial_smoothing_sigma = 1.5
six_segment_warp = true
```

Required fields:

- `lge_mask_bullseye.lge`
- `lge_mask_bullseye.mask`
- `lge_mask_bullseye.lge_scar_mask`

Mapping options use the same defaults and semantics as `[lge_bullseye]`. Relative paths are resolved relative to the TOML file, consistent with existing configuration behavior.

The workflow name added to configuration dispatch is `lge-mask-bullseye`.

## 4. Input Contract and Validation

### 4.1 Accepted data

- LGE: a three-dimensional scalar intensity image readable by SimpleITK.
- Myocardium mask: a three-dimensional scalar mask or a segmentation image whose array representation has a component dimension. NIfTI and `.seg.nrrd` remain supported. Any nonzero label or component denotes myocardium.
- Scar mask: a three-dimensional scalar mask, including the `.nii.gz` generated by `lgeMask`. Any nonzero value denotes scar.

### 4.2 Physical-grid validation

LGE, myocardium mask, and scar mask must have matching:

- size, exactly;
- spacing, with the existing numerical tolerance;
- origin, with the existing numerical tolerance;
- direction, with the existing numerical tolerance.

The workflow never resamples an input. A mismatch raises a `ValueError` describing the mismatched image, field, and values before the annotation UI opens.

### 4.3 Foreground and containment validation

- The myocardium mask must contain at least one foreground voxel.
- An empty scar mask is valid and produces 0% scar for every AHA segment containing myocardium.
- Every scar voxel must be inside the myocardium mask on the full native grid. If any scar voxel lies outside, the workflow stops before annotation and reports the total count of out-of-myocardium scar voxels. It does not silently clip them.

After full-grid validation, all three arrays are cropped to the same first-through-last myocardium-containing slice range. The resulting study retains the existing apex-to-base slice convention.

## 5. Interactive Landmark Behavior

The new command reuses the existing AIP/IIP annotation UI, including zoom and pan support.

- Every invocation starts a fresh annotation session with `resume_existing=False`.
- An existing `<case>_lge_landmarks.json` is never loaded as annotation input.
- A successful new annotation replaces the same landmarks output path.
- A skipped landmark slice uses the existing neighboring-slice interpolation behavior.
- Basal slices marked `Delete` are excluded from intensity mapping, AHA assignment, and scar statistics.
- If no retained slice has a valid AIP/IIP pair, the workflow fails with a clear message.
- If the user closes or cancels annotation, the command returns a nonzero status and does not create new bullseye figures.

The `Skip` behavior here applies only to AIP/IIP landmarks. It is distinct from the normal-reference ROI borrowing rule in the standalone `lgeMask` tool.

## 6. Computation and Outputs

### 6.1 Computation

For retained slices, the shared rendering core:

1. Interpolates missing AIP/IIP landmarks using the existing landmark logic.
2. Assigns native myocardial voxels to AHA segments 1 through 16 using the configured `six_segment_warp` behavior.
3. Maps native LGE intensity to the continuous bullseye grid using the configured angular/radial resolution and smoothing.
4. Computes each segment's scar burden as:

   `scar percentage = scar voxels / myocardial voxels * 100%`

5. Renders the intensity bullseye.
6. Renders the AHA 1-16 scar-percentage bullseye with the existing white-to-orange/red heat scale.

Segment 17 is neither calculated nor displayed. Segments with no myocardial voxels retain the existing not-applicable rendering behavior.

### 6.2 Exact output contract

The new command writes exactly these three case-prefixed artifacts:

- `<case>_lge_landmarks.json`
- `<case>_lge_intensity_bullseye.png`
- `<case>_lge_scar_bullseye.png`

It does not write:

- an intensity NPZ;
- a scar-segment CSV;
- normal-ROI JSON;
- a generated or copied scar mask.

Successful runs overwrite files with the same names. Figure output uses the project's safe temporary-file replacement behavior so a failed save does not corrupt an existing PNG.

## 7. Compatibility of the Complete Workflow

`cardiac-lge-bullseye` keeps its existing `[lge_bullseye]` configuration contract and full interaction sequence. Its seven outputs remain unchanged:

- landmarks JSON;
- intensity NPZ;
- intensity PNG;
- normal-ROI JSON;
- scar-mask NIfTI;
- scar-segment CSV;
- scar bullseye PNG.

The complete workflow may be refactored to call the new shared rendering core, but its user-visible behavior, fresh-annotation rules, scar thresholding, output names, and return object remain compatible.

## 8. Error and CLI Behavior

The CLI follows the existing command pattern:

- `--config` is required.
- Missing files and invalid configuration produce concise stderr output and exit code `1`.
- Invalid dimensions, scalar/component requirements, physical-grid mismatch, an empty myocardium mask, scar containment violations, insufficient landmarks, cancellation, and rendering failures also produce exit code `1`.
- `--help` exits successfully without requiring a configuration file.

Validation that does not require user interaction completes before the AIP/IIP window opens.

## 9. Implementation Scope

Expected production changes are limited to:

- registering the new script in `pyproject.toml`;
- adding the new CLI entry point;
- adding `LgeMaskBullseyeConfig`, parser support, workflow name, and validation;
- adding the new workflow module and public workflow export;
- adding external scar-mask loading and validation to the LGE I/O layer;
- extracting a shared, non-interactive rendering unit from the existing LGE workflow;
- documenting the three-part product structure and adding a copyable TOML example.

Unrelated bullseye, short-axis, coronary, and distance workflows are outside scope.

## 10. Test Strategy and Acceptance Criteria

### 10.1 Configuration and CLI tests

- Parse all new fields, relative paths, Windows paths, and defaults.
- Aggregate missing required input errors.
- Dispatch the new entry point to `lge-mask-bullseye` and its runner.
- Verify `--help`, concise failure output, and exit codes.

### 10.2 I/O validation tests

- Load a NIfTI LGE with a `.seg.nrrd` myocardium mask and a scar NIfTI.
- Reject size, spacing, origin, and direction mismatches.
- Reject non-scalar LGE and unsupported scar dimensions.
- Accept an empty scar mask.
- Reject scar outside myocardium and assert that the message includes the violating voxel count.
- Verify that all arrays use the same myocardium-derived slice crop.

### 10.3 Workflow tests

- Assert that AIP/IIP annotation is called with `resume_existing=False`.
- Assert that normal-ROI selection and `mean + nSD` scar calculation are never invoked by the new workflow.
- Verify landmark interpolation and basal deletion reach the existing mapping functions correctly.
- Verify AHA 1-16 scar percentages from a known synthetic volume.
- Verify that exactly the three specified case-prefixed outputs are returned and written.
- Verify that an empty scar mask produces a 0% scar bullseye.

### 10.4 Regression tests

- Keep the existing full LGE workflow test passing, including all seven outputs.
- Run the complete project test suite to ensure other CLI commands and workflows remain unaffected.

The feature is accepted when both LGE commands use the same mapping/rendering implementation, the new command requires only AIP/IIP interaction, all strict input checks pass, and the complete workflow remains backward compatible.
